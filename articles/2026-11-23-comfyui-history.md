# 从 SD WebUI 到 ComfyUI：节点式 AI 绘图工具是怎么走红的

> 2026-11-23 · 历元技术笔记 · 约 6 分钟阅读

很多人用 AI 绘图时，会把 Stable Diffusion、SD WebUI 和 ComfyUI 混成一个东西，也说不清节点式界面为什么后来成了主流。这篇笔记先分清这三层概念，再按时间线梳理从表单式界面到节点式界面的变化，最后总结 ComfyUI 胜出的几个结构性原因。原始资料里拿不准的年份、数字和人名，我们都删掉了。

## 一、先分清三层概念

讨论这段历史前，要先分清"模型"和"界面"：

| 名称 | 是什么 | 角色类比 |
| --- | --- | --- |
| Stable Diffusion | 扩散模型本身，由 Stability AI、CompVis 等机构参与发布 | 发动机 |
| Stable Diffusion WebUI（AUTOMATIC1111，简称 A1111） | 第一个爆款图形界面，表单式操作 | 第一代驾驶舱 |
| ComfyUI | 后起的节点式（Node-based）图形界面 | 第二代驾驶舱 |

A1111 和 ComfyUI 本质上都是给模型用的"操作台"，自己并不生成图像，能力来自底层模型。两者的区别在交互范式上：

- **表单式（A1111）**：参数按页面和选项卡排好，填完表点"生成"。上手快，但流程基本是固定的。
- **节点式（ComfyUI）**：加载模型、文本编码、采样、解码等环节各是一个独立节点，用户自己连线组成流程，和 Blender 的节点编辑器、Unreal 的蓝图是一类思路。

## 二、发展时间线

### 1. 起点：Stable Diffusion 开源（2022 年 8 月）

Stable Diffusion 开源发布后，普通用户第一次能在自己的显卡上本地跑高质量的文生图模型，AI 绘画由此走向大众。但光有模型权重，普通用户还是很难上手，图形界面就成了刚需。

### 2. A1111 WebUI 成为主流（2022 年下半年）

模型开源后不久，AUTOMATIC1111 发布了 Stable Diffusion WebUI。表单式界面门槛低，加上插件生态很快壮大，它迅速成了社区里的主流工具，在 GitHub 上关注度涨得很快。

### 3. ComfyUI 诞生（2023 年 1 月）

开发者 comfyanonymous 在 GitHub 上发布了 ComfyUI。动机很朴素：表单模式很难表达复杂的生成流程，于是改用节点图重新组织整个流程，每个环节都能拆开、替换、自由连接。

### 4. 转折期（2023 年下半年至 2024 年）

这一时期有三件事一起推动了 ComfyUI 的崛起：

- **新模型支持更快**：SDXL 出来后，ComfyUI 适配新模型的速度开始超过 A1111。
- **视频生成兴起**：AnimateDiff、Stable Video Diffusion 这类视频方案要多阶段、多模型配合，表单式界面很难搭，节点图天然合适。
- **工作流分享文化形成**：调好的工作流可以存成 JSON 文件，别人一键导入就能复现，社区里渐渐有了"工作流即资产"的说法。

### 5. 成为事实标准（2024 年起）

Black Forest Labs 发布 Flux 时，ComfyUI 首日就提供了原生支持。此后，新模型发布时优先适配 ComfyUI 渐渐成了行业惯例，ComfyUI 也从"第三方界面"变成了很多模型事实上的标准运行后端。

同年，核心团队成立了 Comfy Org，开始公司化运营，之后陆续推出桌面版、云端服务和 API 等产品形态，应用范围也从图像扩展到视频、音频等方向。

## 三、A1111 与 ComfyUI 的关系演变

### 阶段一：A1111 主导，ComfyUI 小众

早期 A1111 是绝对主流，ComfyUI 更像极客的工具。它的学习曲线很陡，用户得理解 latent（潜空间）、KSampler（采样器节点）、CLIP（文本编码器）这些概念，换来的是几乎不受限的灵活度。

### 阶段二：分水岭

A1111 的维护节奏明显放慢，社区里出现了不满。期间出现了 Forge 等以性能优化为主的衍生分支，但没能扭转局面。同时，视频模型、Flux 等新范式对流程编排的要求越来越高，表单式架构渐渐跟不上了。

### 阶段三：接班完成

新模型厂商首发就适配 ComfyUI，教程、工作流和商业服务也越来越多地围绕它展开。A1111 仍然能用，但已不是新功能和新模型最先落地的地方。

### 插曲：UI 光谱的另一端

这期间还出现过 Fooocus 这类极简工具，主打类似 Midjourney 的"一键生成"体验。它说明界面设计有一条光谱：

- 一端是 ComfyUI：极度灵活，但复杂；
- 另一端是 Fooocus：极度简单，但可控性有限；
- A1111 夹在中间，灵活性比不上节点式，易用性又比不上极简派，处境最尴尬。这也是 A1111 走下坡路的原因之一。

## 四、为什么最后是 ComfyUI 胜出

我们认为主要有四个结构性原因：

1. **表达力**：扩散模型的用法越来越复杂，多模型串联、视频生成、各种控制条件、音画对齐都要用上。节点图能表达任意流程，表单式界面做不到。
2. **可复现性**：一个工作流 JSON 就是完整配置，分享出去别人就能复现，大大降低了交流和协作成本。
3. **工程友好**：ComfyUI 既是图形界面，也能当 API 和后端服务用。开发者可以完全不碰界面，直接把它接进自己的系统。
4. **社区飞轮**：工作流分享、模型厂商主动适配、大量第三方自定义节点，三者互相促进，生态越大，新来的用户和厂商越倾向于加入。

## 小结

- **概念上**：Stable Diffusion 是模型，A1111 和 ComfyUI 是两代界面，前者表单式，后者节点式。
- **时间线上**：2022 年 8 月模型开源，A1111 随后普及了本地 AI 绘图；2023 年 1 月 ComfyUI 发布，经过 SDXL、视频生成和工作流分享文化的推动，到 2024 年 Flux 首日支持前后，成了新模型的优先适配对象。
- **原因上**：表达力、可复现性、工程友好和社区飞轮四点叠加，让节点式界面在模型应用越来越复杂时占了上风。

一句话概括：Stable Diffusion 提供了引擎，A1111 完成了第一次普及，ComfyUI 则把它从"画图工具"推进成了视觉生成的通用工作台。如今，Stable Diffusion 本身也只是 ComfyUI 支持的众多模型之一。
