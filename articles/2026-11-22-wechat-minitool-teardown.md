# 微信「做个小工具」安装包观察：它是怎么让一句话变成小程序的

> 观察对象：微信「做个小工具」（minitool.weixin.qq.com）Windows x64 Beta 版 `0.01.2611202`（2026-11-21 发布）
> 观察日期：2026-11-22
> 观察方式：只下载官网公开提供的安装包，在文件层面查看目录结构和随包文档。**没有安装运行、没有登录使用，也没有调用任何接口。**

## 一句话结论

**「做个小工具」是微信开发者工具的定制版，里面内置了一个基于开源项目 [opencode](https://github.com/sst/opencode) 改造的 AI 编程助手。**

用户用一句话描述需求，AI 自己写代码、在模拟器里运行并测试，后端部署到微信云开发上，需要的话还会生成一个后台管理页面。

---

## 一、官网能看到的信息

| 项目 | 内容 |
| --- | --- |
| 出品方 | 腾讯官方（域名在 `weixin.qq.com` 下） |
| 下载来源 | 与「微信开发者工具」同一个下载目录 |
| 标语 | 做个小工具 · 让想法发生 |
| 平台 | Windows x64、macOS Intel、macOS Apple 芯片；**没有网页版和手机版** |
| 阶段 | Beta，版本号 0.01；页面有扫码报名入口，大概率需要报名后才能使用 |

官网公开的版本记录显示，11 月中旬至今已经发了两个版本（0.01.2611132、0.01.2611202）。旧版安装包的文件名里能看到 `electron` 和 `opencode` 字样，这是判断技术栈的第一条线索：

- **Electron**：用网页技术做桌面软件的框架，VS Code 和微信开发者工具都用它。
- **opencode**：开源的 AI 编程助手，定位类似 Cursor、Claude Code。

## 二、安装包里有什么

- 安装包约 221 MB，解压后约 3,900 个文件、近 1 GB。
- 核心代码打包在一个约 287 MB 的资源包里，包含 4 万多个文件。

按体积排，占大头的是这几块：

| 体积 | 模块 | 说明 |
| --- | --- | --- |
| 约 150 MB | 小程序 Skyline 渲染引擎 | 小程序的新一代渲染引擎 |
| 约 100 MB | 主要业务代码 | 含改造后的 opencode |
| 约 53 MB | 代码编译工具（SWC） | |
| 约 50 MB | 开发者工具沙箱 | |
| 约 16 MB / 13 MB | 安卓、iOS 真机调试工具 | |
| 约 9 MB | 微信云开发 SDK | |
| 约 1 MB | MCP 协议库 | AI 调用工具的标准协议 |

**结论：本体就是一整套微信开发者工具。** 小程序专用语言（WXML、WXSS、WXS）的编译器、模拟器、云开发 SDK、真机调试、代码编辑器、Git 和终端都在里面。所以它做出来的「小工具」本质上是**小程序类应用**，不是普通网页。

## 三、AI 部分是怎么接上的

AI 助手作为后台进程运行，通过一组内置插件和「技能」（Skill，一种给 AI 的操作说明书）来操作开发者工具。按功能大致分为几类：

| 类别 | 能做什么 |
| --- | --- |
| 小程序开发 | 新建项目、编译、预览、调试、模拟器操作、自动化测试、云开发操作、项目配置 |
| 需求澄清 | 先反过来追问用户，把模糊的需求问清楚 |
| 规划 | 先出方案再动手 |
| 小工具专属 | 生成小工具本体、配套的后台管理页面、操作原生弹窗等界面 |
| 联网搜索 | 调用腾讯的搜索服务查资料 |

另有一组「开发者工具工作流」技能，覆盖项目管理、编译、预览、调试、页面自动化、云函数和云数据库操作。它的安全规则写明：**只调用已注册的工具，不能当作通用编程助手或任意执行命令的终端使用**。这个思路和业内其他 AI 编程产品一致：AI 能做什么，由开放给它的工具清单划定边界。

## 四、做一个小工具的大致流程

根据随包附带的技能说明，可以拼出大致流程：

1. **每个小工具都是一个真实的微信云开发项目**，有自己的 AppID 和云环境，不是本地演示。
2. 用户说出需求后，由一个专门的子任务负责写代码和部署。
3. **自动判断要不要后台**：如果这个工具会留下需要长期保存、并且需要所有者事后查看或修改的数据（比如报名信息），AI 会问一次要不要后台。要的话，它会生成一个**放在本地、不打包进小工具**的管理页面，用来查看和修改云数据库。
4. 规则强调要以**线上实际部署的代码**为准，不能猜接口，也不能拿真实数据随便试改、试删。
5. **在模拟器里自动测试**：AI 能操作授权弹窗、选择器、选文件、地图选点等原生界面；**遇到支付、人脸识别这类环节会停下来，等人处理**。

## 五、用的什么大模型

- 模型列表是**联网远程下发**的，不写死在安装包里。配置格式和 opencode 一致。
- 代码里出现过多家国内外大模型的名字，涉及 OpenAI、阿里通义千问、DeepSeek、智谱 GLM、月之暗面 Kimi、Anthropic Claude、腾讯混元等。
- 代码里还能看到腾讯自家 AI 编程助手的服务通道，**很可能**是默认通道。

> ⚠️ **默认用哪个模型、能不能填自己的 API Key，目前判断不了。** 代码里出现某个模型的名字，只说明支持它的配置格式，不等于实际会用。这需要登录使用后才能确认。

## 六、还没弄清楚的

- 需要报名、登录后才能用，这次没有实际运行。
- 做好的小工具能不能像正式小程序一样**公开发布**、给谁用：从文件看具备「上传」能力，但具体规则不清楚。
- 是否收费、有没有用量限制：不清楚。

## 七、我们的看法

微信正在把开发者工具升级成 **AI 自动开发平台**。「小工具」可以理解为「小程序 + 云后台」的简化版：

- **面向谁**：不会写代码、但有想法的人。
- **适合做什么**：报名登记、抽奖、预约、内部统计这类带数据的轻量工具。
- **优势**：从开发、部署到后台管理，全在一个软件里完成。
- **限制**：做出来的东西离不开微信生态和腾讯云开发。

思路和 Bolt、Lovable、Cursor 这类「用自然语言写程序」的产品一样。区别在于它背靠微信，做出来的东西可以直接在微信里运行和分享，这是其他产品给不了的分发渠道。

## 观察方法

1. 打开官网，找到公开的版本记录和各平台安装包下载地址。
2. 下载 Windows x64 安装包，用解压工具列出文件。
3. 统计核心资源包里各模块的体积，阅读随包附带的技能说明文档。
4. 在文件中检索模型名、工具名，判断技术栈。

全程没有安装或运行程序，没有登录，也没有调用任何接口。
