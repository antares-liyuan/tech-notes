# 一次理清 Model、Harness、Agent、Skill、MCP 是什么关系

> 2026-11-23 · 历元技术笔记 · 约 7 分钟阅读

用 AI 工具时，Model、Harness、Agent、Skill、MCP（再加上 Tool）这几个词经常一起出现，很容易混。这些概念之所以难分清，是因为它们不在同一层，也不是可以互相替换的选项，而是同一套系统里的不同零件。这篇笔记先用一个统一的框架把它们讲清楚，再以开源的 Hermes Agent 为例，看每个零件在实际系统里对应什么。

## 一、先各用一句话定义

我们用"开车"来类比，把每个概念放到对应的位置上：

| 术语 | 一句话本质 | 类比 |
| --- | --- | --- |
| Model（模型） | 大脑：负责推理，决定下一步做什么（如 DeepSeek、Claude、GPT） | 司机的脑子 |
| Harness（运行框架） | 身体和神经系统：跑"想→做→看→再想"的循环，管理上下文、记忆、权限和工具执行（如 Hermes、OpenClaw、Claude Code） | 整辆车：底盘、方向盘、油门 |
| Tool（工具） | 一个原子能力：执行命令、读写文件、联网搜索 | 车上的装置：喇叭、GPS |
| MCP（协议） | 标准插座：让外部工具和数据源即插即用地接入 Harness，不用逐个写死集成 | 车上的 USB / OBD 标准接口 |
| Skill（技能） | 封装好的做事流程（SOP）：告诉 Agent"这类活按这个套路干"，通常会调用多个 Tool | 驾驶手册里的操作规程，比如"如何倒车入库" |
| Agent（智能体） | 以上全部组装起来，再加上一个目标，跑起来的整体 | 司机开着这辆装备齐全的车去干活 |

## 二、关键：它们是分层关系，不是并列选项

把这几个概念画成一张结构图，层次就清楚了：

```
目标 / 任务
     ↓
┌──────────────────────┐
│        AGENT         │  = 整台跑起来的东西
│  ┌────────────────┐  │
│  │ Harness        │  │  ← 运行循环 / 记忆 / 权限
│  │ + Model        │  │  ← 大脑
│  │ + Tools        │  │  ← 手脚（原子能力）
│  │   ↑ MCP ↑      │  │  ← 标准接口：把外部工具和数据接进来
│  │ + Skills       │  │  ← SOP：教它把特定任务做好
│  └────────────────┘  │
└──────────────────────┘
```

每一层各自决定一件事：

- **Model** 决定"聪不聪明"；
- **Harness** 决定"循环稳不稳、会不会纠错、有没有记忆"；
- **Tools** 决定"能做哪些动作"；
- **MCP** 决定"不改代码就能接入多少外部能力和数据"；
- **Skills** 决定"能不能把某类活干得专业且可复用"；
- **Agent** 是这些组合起来后的成品。

## 三、最容易混的三对，专门澄清

**Skill ≠ Tool。** Tool 是原子能力，是一个动词，比如"运行代码"；Skill 是流程，比如"如何做一次代码评审"或"如何整理一份会议纪要"，它会编排调用多个 Tool。一个是"手"，一个是"手册"。

**Skill ≠ MCP。** Skill 提供的是知识，告诉模型应该按什么套路做；MCP 提供的是连接，是把工具和数据源接进来的管道。一个管"知道怎么做"，一个管"能拿到什么工具和数据"。

**Agent ≠ Harness。** Harness 是空车、是框架；Agent 是装上大脑、工具和目标之后跑起来的整体。举个常见的例子：Claude 这个模型运行在 Claude Code 这个 Harness 里，调用各种 Tool，加载若干 Skill，再通过 MCP 连上云盘之类的外部服务，这一整套组合在一起，才是我们日常打交道的那个 Agent。

## 四、落到 Hermes Agent：每个零件对应什么

Hermes Agent 是一个可以自托管的 Agent 运行框架。拿它做例子，可以把上面的抽象概念一一对上：

| 在 Hermes 里 | 具体是什么 | 独特价值 |
| --- | --- | --- |
| Harness = Hermes 本体 | 自托管的运行底座：Agent 循环、上下文与记忆、工具执行、子 Agent、权限控制、消息通道和网关 | 完全掌控、可自托管、成本可控，这是相比"成品智能体"最大的主动权 |
| Model 基座 | 由使用者自行配置的模型，可以切换，也可以设置故障时自动切换 | 决定推理和理解能力的上限，换模型效果可能差别很大 |
| Tools | Hermes 提供给模型的原子能力：shell、文件读写、搜索、浏览器等 | 决定能做哪些动作，没有工具的模型只能"说"不能"做" |
| MCP | 接入 MCP 后，就能即插即用地连接外部工具和数据，比如数据库、协作软件、云盘，也可以把自己的数据接口封装成 MCP server | 扩展性和生态：一次封装，到处复用，不用为每个数据源改代码 |
| Skills | 封装好的做事 SOP，可以按需加载 | 把经验固化下来、可复用、可传承，让不同模型、不同会话都能稳定产出，决定"干得专不专业" |
| Agent | 上面全部，加上一个目标跑起来，就是一个 Hermes Agent 实例 | 真正在"用"的那个能自主干活的整体 |

这里有个值得注意的点：Skills 和 MCP 都是"写一次、到处用"的资产。同一个 Skill 换了底层模型依然可以加载；同一个 MCP server 也可以被不同的 Agent、不同的会话共用。这正是分层设计带来的好处——每一层可以独立替换和升级。

## 五、为什么每一层都重要

我们可以用一个粗略的公式来概括：

> 实战能力 ≈ Model × Harness × (Tools / MCP) × Skills × 纪律

这里用乘法而不是加法，意思是它更像木桶，任何一层塌了，整体就塌了：

- **只有强 Model，没有好 Harness**：不会纠错、没有记忆，任务做到一半就崩；
- **有 Harness，没有 Tools / MCP**：接不到数据，也动不了手；
- **什么都有，唯独没有 Skills**：每次都从零摸索，质量不稳定，经验无法复用；
- **全都有，但没有纪律**：会编造内容，甚至可能执行删库这类危险操作。

最后这一条常被忽视。所谓"纪律"，包括权限边界、危险操作前的确认、对输出结果的核验等。它们一部分由 Harness 的权限机制保证，一部分要写进 Skill 的流程里。

## 六、想提升 Agent，该补哪一层

有了分层视角，排查问题和改进系统就有了方向：

1. **回答质量不够、理解偏差大**：优先考虑换或升级 Model；
2. **长任务中途失败、上下文丢失、不会自我纠正**：问题多半在 Harness 层；
3. **拿不到需要的数据、无法操作某个系统**：补 Tool，或者把对应数据源封装成 MCP server；
4. **同类任务每次结果参差不齐**：把成熟的做法沉淀为 Skill；
5. **出现越权、误操作或编造**：收紧权限配置，并在 Skill 中加入核验步骤。

## 小结

一句话记住：**Model 是大脑，Harness 是车，Tools 是手脚，MCP 是让外设即插即用的标准接口，Skills 是教它把特定活干好的 SOP——把这些组装起来、朝一个目标跑，就是 Agent。**

放到 Hermes 里看：Hermes 提供一辆完全可控的车，Model 决定它有多聪明，MCP 决定它能接入多少外部能力，Skills 决定它把活干得多专业。想提升哪方面，就补哪一层。
