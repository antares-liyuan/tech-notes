# 怎么比较 AI 智能体框架（harness）的强弱

> 2026-11-23 · 历元技术笔记 · 约 6 分钟阅读

同一个智能体框架（harness）换一个底层模型，表现可能差很多。所以框架的“强弱”要在控制变量之后才能比。这篇笔记整理了我们用的评判维度和实测方法，最后附上几款常见框架的定性对比。

## 一、先厘清：比的到底是什么

harness 指包在大模型外面的那层“外壳”：它负责 Agent 循环、上下文管理、工具调用、权限控制和对外接口。直接比较“哪个 harness 分数高”，其实比的是模型、harness 和策略三者叠在一起的结果。

所以我们关心的问题是：**用同一个模型、做同一批任务时，这套外壳能把模型的能力发挥出多少，少崩多少次，少让人接手多少次。**

## 二、评判 harness 的 10 个维度

| 维度 | 看什么 | 为什么重要 |
|---|---|---|
| 1. Agent 循环质量 / 自主性 | 多步规划、出错后自己恢复、知道何时停 | 决定长任务能不能自己跑完而不中途崩掉 |
| 2. 上下文 / 记忆管理 | 上下文压缩、跨会话的持久记忆、检索 | 决定任务变长后会不会“失忆”或质量下降 |
| 3. 工具生态与扩展性 | 内置工具多不多、是否支持 MCP、能否自定义工具或 skill | 决定能接入多少外部能力和数据 |
| 4. 模型灵活性 | 只能用一家的模型还是可换任意模型、能否故障切换 | 决定能否按需选择低成本、最强或本地模型 |
| 5. Skills / 可复用流程 | 能否把标准流程（SOP）封装复用、生态规模 | 决定特定任务做得是否专业、稳定 |
| 6. 多 Agent / 编排 | 子 Agent、并行执行、workflow | 决定能否拆分并行处理大任务 |
| 7. 安全 / 权限 / 沙箱 | 权限模型、审批机制、沙箱隔离 | 决定能否放心让它操作真实环境 |
| 8. 接口 / 集成 | CLI、IDE、消息机器人桥接、gateway、定时任务、headless 模式 | 决定能否嵌进已有的自动化流程 |
| 9. 可靠性 / 生产就绪 | 稳定性、可观测性、断点续跑 | 决定能否把正式工作交给它 |
| 10. 控制权 / 自托管 / 成本 | 是否开源、能否自托管、隐私、成本是否可控 | 决定控制权在厂商手里还是在使用者手里 |

## 三、怎么实测：三种方法，从硬到软

**1. 控制变量盲测（最可靠）**

固定同一个模型（例如全部接同一个 Claude 或 DeepSeek 模型），用同一批任务分别跑几个 harness，记录以下指标：

- 成功率
- 完成所用步数
- 出错后能否自己恢复
- 人工干预次数
- token 成本

只有这样，才能把“harness 本身的贡献”单独分离出来。任务集最好贴近真实场景，比如一组电脑操作任务或一组研究类任务，执行时尽量不让评分者知道是哪个框架跑的。

**2. 公开的 Agentic 基准（横向参考）**

SWE-bench Verified、Terminal-Bench 这类基准可以拿来参考。不过它们和 OSWorld 一样，分数是“模型 + harness + 策略”的系统分，不是 harness 单独的分数，只能横向看个大概。

**3. 定性观察（最能看出工程功力）**

故意给一个中途会出错的多步任务，重点观察三件事：

- 出错后怎么定位问题、怎么纠正；
- 上下文快满时怎么压缩，压缩后有没有丢掉关键信息；
- 遇到敏感操作时怎么请求权限。

## 四、各维度具体看什么

- **循环 / 自主性**：看它是否“知道何时停”。有的框架会无限重试，有的过早宣布完成，两种都算扣分。
- **上下文 / 记忆**：在长任务的后半段，抽查它是否还记得前面约定的约束条件。
- **工具 / 扩展**：接一个自定义 MCP 工具或 skill，看接入成本高不高，调用是否稳定。
- **安全 / 权限**：看默认权限是否保守、审批粒度能否细到单个命令、有没有沙箱。
- **可靠性**：中途人为中断，看能否从断点继续；同时看日志和可观测性是否足以复盘。
- **成本**：同一任务的 token 消耗，加上能否换用更便宜的模型。

## 五、几款框架的定性对比

> 以下对比基于公开资料与使用体验，未做严格基准测试。这类产品更新很快；开源自托管类框架的表现又很依赖具体配置（接了哪些工具、skill 和模型），所以这里给的只是大致画像，不是定论。

| 维度 | Claude Code | Codex（CLI） | OpenClaw | Hermes |
|---|---|---|---|---|
| 定位 | Anthropic 官方的 agentic 编码 / 通用 harness | OpenAI 官方的 CLI Agent | 开源、不绑定模型的自托管 harness | 自托管 harness |
| 模型 | 主要配 Claude | 主要配 OpenAI 模型 | 可接多家及本地模型 | 可接多家模型 |
| 循环 / 自主性 | 强，纠错能力好 | 较强 | 取决于配置 | 取决于配置 |
| 上下文 / 记忆 | 强（压缩 + 持久记忆） | 较强 | 中等 | 中等 |
| 工具 / MCP / skills | 强（MCP、skills、hooks、子 Agent） | 较强 | 较强（skills、MCP、浏览器） | 取决于配置 |
| 多 Agent / 编排 | 强（子 Agent、workflow） | 中等 | 较强 | 中等 |
| 安全 / 权限 | 强（权限模式、审批、hooks） | 较强（沙箱） | 中等 | 中等 |
| 接口集成 | CLI、IDE、SDK、远程 | CLI、云端 | 消息桥接、gateway、定时任务 | 消息桥接、gateway |
| 生产就绪 | 成熟 | 较成熟 | 需自行打磨 | 需自行打磨 |
| 控制权 / 自托管 | 弱（闭源、绑定厂商） | 中等（CLI 开源但绑定模型） | 强（开源自托管、可换低成本模型） | 强（完全自主掌控） |
| 文档 / 社区 | 完善 | 较完善 | 一般 | 较小众 |

## 六、关键分野：两种路线

大致可以分成两派：

- **厂商精装派（Claude Code、Codex）**：和自家模型深度耦合，开箱即用的 agentic 能力强，开发体验好，也更稳定。代价是绑定厂商，闭源或半闭源，控制权和成本在别人手里。
- **开源自托管派（OpenClaw、Hermes）**：不绑定模型，可以自托管，可以换成更便宜的模型，也能深度定制，成本和隐私自己掌握。代价是要自己搭建和调优，开箱时的稳定性和打磨程度通常不如前者。

所以在我们的实践里，两类不必二选一：需要最强推理的攻坚任务交给厂商精装派，大量、常态化、对成本和隐私敏感的自动化任务交给自托管派。

## 小结

- harness 的强弱必须在**同模型、同任务**的前提下比较，否则比的是系统分，不是外壳本身。
- 我们用 10 个维度做评判框架，重点关注自主性、上下文管理、工具扩展、安全权限和生产可靠性。
- 最硬的方法是控制变量盲测，记录成功率、步数、自恢复、人工干预和 token 成本。公开基准只能横向参考，定性观察用来补充。
- 没有绝对的赢家，“最强”永远取决于任务类型和所配的模型。任何排名（包括本文的表格）都不能替代用自己的任务集实测。
